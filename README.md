# 稀疏地形重建文章日报

这个仓库计划每天北京时间 10:00 运行一次，检索 OpenAlex 中与以下主题相关的文章。工作流使用 `Asia/Shanghai` 时区；GitHub Actions 定时任务可能排队延迟，不能保证准点送达。

- 稀疏地形重建
- 稀疏 DEM 重建与修复
- 数字高程模型补全
- 地形表面重建与插值
- 点云高程补全
- 遥感 DEM 缺失区域修复

脚本会筛选最多 8 篇高相关结果，优先最新发表；近期期刊论文不足时，也检索 2018 年以来尚未收录的相关成果。每篇标明“近30天发表”或“历史未收录补充”。论文必须同时涉及地形/高程等核心对象以及重建、补全、修复或插值任务；不靠低相关内容凑数量。已发送论文记录在 `seen_papers.json`，后续运行不重复推送。日报发布到固定 Issue 并 @ 仓库所有者，GitHub 依通知设置发送邮件。本仓库没有直接连接企业微信机器人；企业微信实际到达时间还受仓库外的转发链路影响。

## 已有文献排除

`known_papers.json` 保存从《论文梳理_地形恢复.docx》提取的文献：85 条文献条目合并重复后为 83 篇，包含 100 个标题及标题别名。没有上传原文档或研究笔记。无 DOI 的条目通过标题匹配，统一大小写、空格、标点、连字符和全角字符，并移除文档中附加的期刊名。标题的完整翻译或大幅改写不能仅靠此匹配识别；这类条目可补充 DOI 或原文标题作为别名。

每次检索同时排除 `known_papers.json` 中的已有文献和 `seen_papers.json` 中的推送记录，再按发表日期由新到旧选择最多 8 篇。同一期也按 DOI、来源链接和标题去重。检索覆盖 OpenAlex 每组查询近期及历史窗口的前 100 条结果，并非数据库穷尽检索；没有新论文时不发送通知。

`local_catalog_keys.json` 是从本机历史台账的 128 条记录提取 DOI/英文题名后生成的 SHA-256 排除索引，只上传不可直接阅读的哈希值，不上传台账正文、学校账户或 PDF。它是当前快照；以后手动向本地台账增补论文时，需要同步更新这个索引，云端才会知道该文已收录。已推送的论文则由 `seen_papers.json` 自动排除。

## 日报梳理格式

每篇论文按《科研文献简要阅读固定提示词_完整版.docx》的阅读笔记结构输出：期刊与论文基本信息、研究背景、核心方法、创新点、实验结果、结论，以及一句话通俗理解。基本信息包含题名、作者、日期、期刊/来源、DOI、研究方向、相关性和按论文目录自动初分的交叉类别。JCR 和中科院分区都标为“未核验”，直到获得注明年份和来源的可靠分区数据；预印本不能误写成期刊。每篇都注明仅据 OpenAlex 摘要和元数据，**不是全文精读**；摘要未说明的实验数值、作者局限和未来工作不会补造。邮件中的简报因此比示例的全文阅读笔记短。

可选的摘要整理步骤会把摘要交给自建 OpenAI 兼容接口，生成中文段落，并要求每段返回一段可在原摘要中逐字找到的证据；缺证据的段落回退为保守模板。该校验不能替代核读论文全文，也不保证自动翻译绝对无误。没有配置 API 密钥时完全不调用中转接口，采用结构化元数据/摘要模板，部分依据保留英文原句。

可在手动运行时勾选 `dry_run`，仅生成预览和运行验证，不发布 Issue 通知或更新推送记录。正式运行将**同一次筛选**的推送正文及结构化清单保存到 `reports/daily/YYYY-MM-DD.md/.json`，供本机同步，不把 PDF 或账号信息提交到仓库。

## 配置 GitHub Secrets

在仓库的 **Settings -> Secrets and variables -> Actions** 中可选配置：

1. `OPENALEX_MAILTO`：用于 OpenAlex 礼貌池的邮箱，可选。
2. `SUMMARY_API_KEY`：自建中转接口的专用密钥，可选；应在 GitHub Actions **Secret** 中设置，不要写进代码或 Issue。配置后最多对当日入选的 8 篇各调用一次，可能产生模型费用。

可选的 GitHub Actions **Variables**：`SUMMARY_API_BASE_URL`（默认 `https://www.lwjcode.xyz/v1`）和 `SUMMARY_MODEL`（默认 `gpt-5.6-terra`）。仅接受 HTTPS 接口；接口不可用时回退为摘要模板。不要把账号密码或学校图书馆 Cookie 配置到本仓库。JCR/中科院分区没有已核验数据时标为“未核验”，不自动猜测。

日报正文通过 GitHub 通知邮件发送，不需要 PushPlus Token 或 SMTP 密码。

## 手动测试

打开仓库的 **Actions -> Daily sparse terrain paper digest -> Run workflow**，可以立即运行一次。运行成功后，日报会出现在固定的 `[论文日报] 稀疏地形重建文章日报` Issue 中，并触发 GitHub 邮件通知。

本地运行：

```powershell
python -m pip install -r requirements.txt
python paper_digest.py --output digest.md --state seen_papers.json
```

## 本机归档

本机执行 `sync_local.ps1` 会只读获取远端 `main` 的日报归档，更新 `E:\论文\知识点概述\日常文献查询记录\稀疏地形重建文献总表.xlsx`，并从归档正文生成同日 Word 简报。目录沿用既有《文献收录与阅读台账.json》的历史记录，**不会重写旧台账或覆盖已有目录行的人工修改**。Excel 区分论文发表日期与本次收录/推送日期，并保留期刊、分区待核验、交叉分类和 PDF 路径。

只有标为“高相关”且 OpenAlex 提供合法开放获取 PDF 地址的论文，才会尝试下载到 `论文\YYYY-MM-DD\英文题名.pdf`。下载前验证 HTTPS、大小及 PDF 头尾；失败会在次日重新尝试。开放获取全文下载成功不表示已核读全文；简报仍以当时推送的摘要级内容为准。订阅期刊如无开放获取版本，不会用学校登录凭据自动抓取，需通过有权访问的图书馆页面另行获取。

本机同步依赖本地 Python 虚拟环境（`python -m venv .venv`、`.venv\Scripts\python -m pip install -r requirements.txt`）以及 Codex 捆绑 Node 运行时及 `@oai/artifact-tool`。GitHub 云端不能直接写本机 E 盘。电脑须开机、联网且 E 盘可用；错过同步的日报将在下次运行时补齐。Windows 计划任务仅负责本机同步，不改变 GitHub/企业微信到达时间。日志在 E 盘目录的 `本地同步日志_UTF8.txt`。
